# 工作台 · 自动化任务 prompt

这个文件夹放的是给 **WorkBuddy 自动任务**（或任何外部调度器）用的提示词。
分工原则：**时间、日期、计算这类本地活归工作台自己；定时、联网的内容生产
搬到 WorkBuddy 上跑**，两边通过本地文件 / 本地 HTTP 接口（127.0.0.1:39217）交接。

## 两类任务，别混

| 类别 | 时机 | 文件 | 依赖 | 特点 |
| --- | --- | --- | --- | --- |
| **每日一刷** | 每天 **0 点后**（00:00–00:10） | `每日预生成.md` | 不要求应用在运行 | 走 exe 的 `--prefetch` 无窗口模式，备好当天简报缓存就退出；明早打开秒出新内容 |
| **实时刷新** | 想换就换（应用开着时） | `壁纸重算.md` | 要求应用在运行 | 只重算壁纸这一件事，不碰简报不碰图库，几秒完成 |

核心区别：每日一刷是**给缓存**（夜里偷偷干，结果第二天才被看到）；
实时刷新是**给当下**（用户在场，立刻要看到效果）。

## 怎么接入

**方式一：AI 助手的自动任务（推荐）**
在 AI 助手（如 WorkBuddy）对话里说：「帮我建一个每天 0 点 5 分的自动任务，提示词就用
`prompts\每日预生成.md` 里的内容」，
把文件内容原样贴进提示词即可——每个文件都是自包含的（路径、校验、失败策略都在里面）。

**方式二：外部调度器**

```bash
# 每日一刷：预生成当天缓存（无窗口，跑完自动退出）
"%LOCALAPPDATA%\Programs\Workbench\Workbench.exe" --prefetch

# 实时刷新：只重算壁纸（要求应用正在运行）
curl -s -X POST http://127.0.0.1:39217/api/wallpaper
```

## 接口/模式速查

| 入口 | 类型 | 作用 | 依赖应用在运行 |
| --- | --- | --- | --- |
| `Workbench.exe --prefetch` | 命令行 | 无窗口预生成**当天**简报缓存后退出 | 否 |
| `GET /api/ping` | HTTP | 探活 | 是 |
| `POST /api/refresh` | HTTP | 实时重建整份简报（手动强刷用） | 是 |
| `POST /api/wallpaper` | HTTP | 实时只重算壁纸（顺带刷天气） | 是 |
| `GET /api/state` | HTTP | 读全部状态（`daily.*`、`photos.chosen`） | 是 |

缓存文件：`%APPDATA%\Workbench\cache\daily-<YYYY-MM-DD>.json`
（每日一刷的产出，只读校验、不要手改。）

## 铁律（写自动化时必读）

1. **每日一刷不许碰 HTTP 接口**——0 点应用多半没开；`--prefetch` 就是为
   这个场景设计的（不绑端口、不拿实例锁、不开窗口）。同理也不许在
   23:50 前后跑，那会算错日期。
2. **实时刷新不许重建简报**——用户在场时要的是快；整份简报重建要几分钟，
   那是每日一刷的活。
3. **工作台可能没开**。实时类任务第一步都先探 `/api/ping`，不通就静默跳过，
   不要尝试启动应用（会弹窗口打扰用户）。
4. **绝对不要调 `/api/quit`**，也不要动 `/api/config`、`/api/launchers`、
   `/api/todos`——自动化只管「刷新内容」，别碰用户数据。
5. **模型 API Key 存在本机配置里**，应用自己会用。自动化里不要出现、
   不要传输、不要索要这个 Key。
6. 服务只绑 127.0.0.1；curl 这类不带 Origin 头的请求会被同源校验放行，
   普通网页跨站请求会被 403 拦掉，属于正常防护。
